# Lab 33 – Triggers — DELETE (BEFORE and AFTER)

## Objective

To learn how to use BEFORE DELETE and AFTER DELETE triggers on the `Employee` table to control employee deletion and maintain a deletion log.

## Tasks

The following trigger operations were performed:

1. Created a BEFORE DELETE trigger `trg_before_delete_employee` on the `Employee` table.
2. Configured the trigger to prevent deletion of employees whose salary is greater than `100000`.
3. Disabled MySQL safe update mode using `SET SQL_SAFE_UPDATES = 0`.
4. Displayed employee IDs and salaries before attempting deletion.
5. Attempted to delete employees with salary greater than `100000` and observed the error generated by the trigger.
6. Verified that the protected employees were not deleted.
7. Created an AFTER DELETE trigger `trg_after_delete_employee` to record deleted employees in the `Employee_Log` table.
8. Deleted employee ID `7` when the salary was less than `100000`.
9. Verified that the deletion was recorded in the `Employee_Log` table.
10. Dropped the `trg_before_delete_employee` trigger.
11. Displayed all remaining triggers using `SHOW TRIGGERS`.

## SQL Concepts Learned

* Creating BEFORE DELETE triggers
* Creating AFTER DELETE triggers
* Using `OLD` values in DELETE triggers
* Using `SIGNAL SQLSTATE` to prevent deletion
* Applying conditions before deleting records
* Using `SET SQL_SAFE_UPDATES`
* Automatically logging deleted records
* Using triggers with a log table
* Dropping triggers using `DROP TRIGGER`
* Viewing triggers using `SHOW TRIGGERS`

## Result

The BEFORE DELETE trigger prevented deletion of employees whose salary was greater than `100000` by generating a custom error. The AFTER DELETE trigger recorded the employee ID and `DELETE` action in the `Employee_Log` table when an allowed deletion was performed. The BEFORE DELETE trigger was then dropped and the remaining triggers were displayed.
